# ENG2040 Assignment 1

This submission implements the complete data pipeline for the modified marketplace extract. It uses SQLite and matplotlib; the supplied `data/raw.sql` is never changed.

## Set up and run everything

Python 3.10 or later and `uv` are recommended. From this folder run:

```sh
uv sync
uv run python pipeline.py
```

The command creates `marketplace.sqlite` if it is absent, rebuilds every numbered data artifact, runs the checks, and rebuilds all report figures, sensitivity CSVs and LaTeX evidence tables. A successful run reports that every validation check passed. The written report is submitted separately and is excluded from the project ZIP. Its PDF compilation is separate.

Matplotlib is the only direct third-party Python dependency and is locked in
`uv.lock`. No database server or model training is required. The report is a
separate LaTeX deliverable; it is not generated by this data pipeline.

## Code structure

`pipeline.py` is intentionally only the command-line entry point. The implementation is organized by responsibility in `marketplace_pipeline/`:

| Module | Responsibility |
|---|---|
| `runner.py` | Runs the stages in order and records their resources. |
| `loading.py` | Creates/opens SQLite and profiles schema, keys, relationships and totals. |
| `cleaning.py` | Assembles one row per order, cleans fields, audits issues and creates labels. |
| `analysis.py` | Produces the three business analyses, chart data and charts. |
| `features.py` | Builds the aligned numerical features, order IDs, labels and dictionary. |
| `validation.py` | Checks accounting, alignment, target boundaries and leakage. |
| `documentation.py` | Saves the executed SQL and environment details. |
| `monitoring.py` | Samples process memory and scoped temporary storage; sizes retained Python data. |
| `report_evidence.py` | Recreates supplementary analysis evidence without needing the separately submitted report folder. |
| `queries.py` | Keeps the executed SQL in one inspectable place. |
| `config.py` | Central paths and fixed dataset definitions. |
| `common.py` | Shared CSV, statistics, matplotlib and resource helpers. |

Each stage exposes one main function; stage-specific details remain inside its module. This keeps the entry command stable while making individual assignment sections easy to find and maintain.

## Important definitions

- One cleaned row represents one source order.
- `delivered_after_estimate = 1` only when a reliable completed delivery occurred after the estimated local calendar date. Delivery on that date is `0` even if its clock time is later.
- Cancelled, unknown, missing, invalid, or chronologically unreliable outcomes stay unlabelled; they are not changed to zero.
- Status and Brazilian state codes are trimmed and case-normalized. Raw values remain in the cleaned file.
- Missing optional catalogue data never removes an order. Missing/invalid approval-time inputs use zero plus an explicit indicator in the numerical feature matrix.
- Negative price/freight components are omitted from the corresponding valid sum and counted in a separate feature. Unsupported upper cut-offs are not invented.
- Payments, final status, shipment/delivery events, reviews, and `shipping_limit_date` never enter the predictor matrix.

## Evidence and interpretation

Results and supporting evidence are saved in the numbered `outputs/` folders, including checks, SQL, environment details, and resource measurements. Findings describe this modified extract; associations do not establish causation.

`outputs/05_documentation/resources.csv` compares estimated and measured resource use. Python allocations, process resident memory, retained data, and temporary storage have different measurement scopes. Sampling occurs approximately every 20 ms and can miss brief peaks. See the CSV's scope descriptions and `marketplace_pipeline/monitoring.py` for details. Database setup explicitly distinguishes fresh import from reuse.

Run the focused regression tests with:

```sh
uv run python -m unittest discover -s tests -v
```
